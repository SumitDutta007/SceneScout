1. The problem, and why I picked it

[Rewrite in your own words.] Today an editor watches every episode of every show to find promo moments, and a new show ships every week. That cost grows with the catalogue and repeats forever, so it is the highest-leverage place to automate. The input also suits a tool unusually well: the scripts are timestamped cue by cue (camera, action, sound, dialogue with emotion tags), so the tool can return exact cut points an editor can act on. And the output is checkable, because every pick traces back to script lines.

2. Assumptions (where the brief was silent)

  • Script time ≈ final-cut time, within a second or two. Boundaries are re-snapped on the video before cutting.
  • A promo is 20–60s. The hook sits in the first 3s of segment 1, the cliffhanger in the last ~4–6s. Stitched promos are 2–3 segments in story order. Cuts land only on a shot change, never mid-line.
  • The output is a shortlist for an editor, not auto-posted clips. The goal is new-viewer acquisition, so early-episode entry points rank higher and late-arc payoffs (ep 39+) are held back. The title already gives away "He was a Duke", so that reveal isn't a spoiler.
  • Every show arrives in this script format.

3. How it works

Parse → legal cut points → rule scores → candidates → LLM judge → select → posting order → quality flags → JSON / report / HTML viewer. One command: python -m promo_finder "data/<show>" --mode hybrid --provider gemini|claude.

4. Scale and cost (measured on the full 50-episode show)

  • Rules-only: 3.8s, $0.
  • Hybrid: 12 LLM calls, 2.5 min, 269k input + 49k output tokens, $0 on Gemini's free tier. The same token count would cost about $2/show at Claude Opus 5.5 prices or about $0.05 at Haiku 5.5 prices. Batching 5 episodes per call cut the calls from ~52 to 12. Responses are disk-cached, so re-runs are free.
  • Free tier is a prototype only: 20 requests/day/model (I hit it on the first, unbatched run), and Google may use free-tier inputs. Production needs a paid tier.
  • Editor time: from watching ~100 min of footage per show to reviewing about 30 shortlisted clips with script excerpts (≈20–30 min; my assumption).
  • Catalogue-scale risks: main cast is derived per show, but speaker aliases (THE FORMER GROOM→Gerald) are a hand-made map. Scripts that don't describe the music weaken the rule cliffhanger signal. A new script format needs a new parser. LLM model churn: two Gemini model IDs were already retired or hanging during this build, so the model is a flag, not hard-coded.

5. How I know it's good, and where it fails

Automated checks (9 tests, all passing): all 50 episodes parse; ep 6's missing scene end is repaired; no cut splits a line; candidates are 20–60s and in story order; the ep 3 proposal cliffhanger is found; LLM output with bad cue IDs or bad lengths is rejected.

Evaluation against fixed picks: before the LLM run, I listed 12 must-have moments (ep 1 altar betrayal, ep 3 proposal, ep 12–13 thorn ultimatum and crawl, ep 24 strike, ep 27 ring reveal, ep 32 hot iron, ep 36 "dead Duke", ep 41 explosion…). These are my picks, not an editor's, so treat this as a sanity check, not ground truth. A moment counts as found if a promo covers ≥50% of it (raw_outputs/eval_vs_my_picks.json).

Main finding: finding moments works; choosing among them doesn't yet. Both engines surface nearly every big moment. The LLM fixed the rules' worst failure: it understood the story, so it stopped picking music-swell endings where nothing is left open. It also found the ep 24 strike, the ep 41 explosion and the ep 26 ring recognition that the rules under-rated. But it rated almost everything 5/5, so its scores don't separate good from great, and the final top 15 dropped the ep 1 opener and the ep 3 proposal. It also kept 4 late-season clips even though its own strategy said to hold them.

Other failures seen in real runs: the rules trigger on stage-direction words ("sneering grin", a gavel "striking" the desk) and trust the writer's music notes. They score only a clip's ends, so peaks buried mid-clip are missed (ep 16, ep 18). The LLM wrote paraphrased hooks ("The visceral image of…") where an editor needs the actual line, which the report shows next to each one. The LLM proposed clips up to 73s and out-of-order stitches, all caught by the validator. And nothing has been checked against real video timing yet.

Next fixes, in order: (1) replace 1–5 scores with pairwise "which promo is better?" comparisons, to fix score saturation; (2) show the editor the top ~30 from the pool (11/12 recall) instead of a hard top 15; (3) build a real gold set from editors' past cuts (--gold reports precision@k and temporal IoU); (4) the final judge is promo performance: 3-second hold rate and click-through to ep 1.
